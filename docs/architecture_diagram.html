Every connection, in detail

The same connections as a table, for scanning quickly or looking up one hop.

From → ToPathProtocol / AuthWhat moves
Foodics → Backend API primary HTTPS, per-brand bearer token Products, modifier groups and options, branches. Pulled every 5 minutes by FoodicsAutoSyncHostedService, or on demand from the portal.
Backend API → SQL Server primary EF Core, SQL login swish_api All reads and writes to every table. The API is the only thing holding database credentials, and that login can't touch the schema.
Web App Portal ↔ Backend API primary HTTPS, header X-Api-Key Brand and branch management, menu item and modifier weights, tablet registration (issues device keys), training-data export, analytics.
Tablet App ↔ Backend API primary HTTPS, header X-Device-Key Pulls the synced menu, weights, and the AI weight model. Pushes each completed weigh event, with the order's full item and modifier list, queued locally and retried if the tablet is offline.
Tablet App ↔ Physical Scale primary USB-Serial over OTG cable Live weight readings. The tablet polls the scale (W↵) about 4 times a second, using the 8217 Mettler-Toledo protocol.
Tablet App → Foodics support HTTPS, per-brand token The live order queue, fetched straight from Foodics using a token built into the APK. Bypasses the Backend API.

AI weight model training pipeline

How a trained weight model gets made from weighed orders data to an AI model that the smart scale can load.

StageStatusWhat it does
WeighEvents / uploaded history existing The same data the Training Data export already reads. Upload is only for backfilling orders that predate the system.
Feature encoding existing The item/modifier keys are already in the export. The item|modifier composite pairing is new logic the training script adds on top, by joining on LineIndex.
Training job planned A Python service the API invokes on demand. Ridge regression, regularized toward the manual entry prior, refit per (item, modifier) pairing.
Model export (.tflite) planned Converting the fitted weights into the binary format for the tablet to load.
BrandWeightModels → Tablet App existing Versioning, hashing, and on-device delivery are already built and working. Publishing a new model reuses this path unchanged.
Missing-item eval planned A search over which an order's own components best explains a measured shortfall.
